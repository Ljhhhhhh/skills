# HTML 讲解页（单文件 · 16:9 · 可翻页）

做法：**内容写成结构化 `deck.md` → `build.py` 套设计系统生成 HTML → `shot.js` 截图并自动查越界 → 看总览图 → `key.js` 测交互 → 用户可见内容审查**。
脚本和模板都在本 skill 目录（下文 `$SK` 指本目录）。依赖：Python 3（总览图需 Pillow），Node 20+，`playwright-core` 和本机 Chrome/Chromium（见 README）。

---

## 0. 先定"什么算做好"（动手前写下来）

完成判定，**全部满足才交付**：

1. `python3 $SK/scripts/build.py deck.md --strict` 0 warning（超字数预算就改写或拆页，不要硬塞）。
2. `node $SK/scripts/shot.js deck.html` 输出 `CLEAN`（0 条 OUT/CLIP/SMALL/HSCROLL/OVERLAP/JSERR），桌面 1600×900 和手机 390×844 都过。
3. `node $SK/scripts/key.js deck.html` 输出 `ALL PASS`，包含目录跳转、常驻导航、首尾禁用和手机目录检查。
4. 你**亲眼看过**桌面总览图和手机总览图，§5 清单逐条过。
5. 页面上没有任何制作过程话术（§6）；主题目录、页面总览和导航按钮符合 §4.1–4.3。
6. 交付物是一个 `.html` 文件，双击就能离线打开（字体用系统字体，不引外部 CDN）。

## 1. 读懂原文，再拆结构（不要边读边做页）

先写一段给自己看的"骨架"，不进页面：

- **一句话主张**：读者合上页面后能复述的那句话，30 字以内。会放在封面的 `thesis` 和结尾页。
- **N 个要点**：每个要点 = 一个独立观点。超过 12 个就合并，少于 3 个就不该做成讲解页。
- **分组**：2–4 组，每组 2–5 个要点；组名 ≤ 4 个字（如"准备 / 执行 / 验证"）。没有天然分组就不分（不写 section）。
- **每个要点三件事**：
  - `problem`：常见做法哪里不对，1–2 句，**最后一句是结论**（会自动加粗）。
  - `action`：具体怎么做，读者明天能照着做的动作，带数字或判据更好。
  - `visual`：用哪种图把它讲清楚（§3 选型表）。**图要能解释观点，不是装饰。**
- **收束**：要点能串成循环就用 `loop`；否则用 `statement` 或 `stats` 收。最后一页 `end` 放一句话主张。

内容类型 → 推荐页序：

| 内容类型 | 页序 |
|---|---|
| 方法论/原则（N 条） | cover → agenda → [section → point×k]×组 → loop → end |
| 选型/对比/数据 | cover → statement(结论先行, bars) → compare(表) → stats → point×(每个关键差异) → cards(各自适合谁) → end |
| 教程/流程 | cover → cards(前置条件) → agenda 或 flow(全流程) → [section(阶段) → point×步]… → list(常见坑) → compare(何时不用) → end |

> 全宽 `steps` 最多 6 步。教程超过 6 步时，主题目录用 `agenda`（自动按阶段分栏），或把流程拆成两页 flow；有多个章节时仍须保留主题目录。
| 报告/观点文章 | cover → statement → point×k → quote → stats → end |

规模：12–22 页最佳。一页只讲一件事。

## 2. 写 `deck.md`（结构化文案）

```
---
title: 浏览器标签页标题
brand: 页脚品牌名（≤10 字）
lang: zh-CN            # 或 en
label: 做法             # point 页黑卡片上的小标签，可省略
---

## cover
kicker: 小标题（≤10 字）
title: 第一行<br>第二行<br>*强调行*      # 每行 ≤7 个汉字（有 orb 时）/ ≤10（无 orb）
sub: 4 组 · 12 条          # " · " 会变成彩色分隔点
thesis: 一句话主张，≤2 行（≤90 字宽）
orb: auto                  # 右侧轨道编号点 = point 页数（auto 自动数）；不要就删掉 orb 和 core
core: 小字 | 大字 / 第二行  # 轨道中心

## section 准备              # 标题也可写在 ## 后面
sub: 一句副标题
                             # 自动列出本组的 point，不用手写

## point 先写结论，再写理由     # 标题 ≤21 字宽，一行
problem: 问题描述。最后一句是结论。
action: 具体做法。
visual: vs                   # 选一个组件（§3）
left: 左栏标题
right: 右栏标题
- 左1 | 右1                   # 行数据：单元格用 " | " 分隔（两侧要有空格）
- 左2 | 右2
note: 可选，图下方一句口语化点评

## compare                    # = full 页 + table 组件
title: 三种方案怎么选
lead: 一句导语
cols: 维度 | 方案 A | 方案 B
win: 方案 B                   # 推荐列高亮
- 成本 | 低 | ✓ 中             # ✓ 开头变绿，✗ 开头变灰。✓/✗ 的意思是「这个方案在这一行占优/不占优」，win 列应以 ✓ 为主（build 会查）

## end
kicker: 带走这一句
title: 一句话主张，<br>*强调*。
ty: 谢谢
- 关键词1
- 关键词2
```

规则：
- 字段名是英文 `key:`，值里不要再出现 `xxx:` 开头的整行（会被当字段）。值可以折行续写。
- 行内只有四种标记：`**加粗**`、`*强调色*`、`==荧光底==`、`<br>`。其他 HTML 都会被转义。
- `accent: 1–4` 可单页换强调色；默认跟随所在 section（1 珊瑚 / 2 紫 / 3 青 / 4 琥珀）。
- `kicker` 不写时 point/full 页自动用所在 section 名。
- 文案里写的"N 条/N 个要点/N 个原则/N points/principles/tips/rules"必须等于 point 页数（build 会查这些词；"N 步""N 个方法"不查，要自己核对）；删改要点后记得同步封面、总览标题。
- 需要组件库没有的专属示意图（决策树、架构图、时间线）：用 `## html` 页，放 ```` ```html ```` 代码块写内联 SVG/HTML。规则：
  - SVG 用 `viewBox` + `style="width:100%;height:auto"`，字号按 viewBox 写 ≥22；文字和方框之间留 ≥8 单位空隙（脚本会报 `OVERLAP`）。
  - 手机上 SVG 会等比缩小到看不清（脚本报 `SMALL svg text`）。二选一：外面包 `<div class="wide" style="--mw:760px">…</div>`（手机横向滑动看），或做两份：`<div class="only-d">桌面版</div><div class="only-m">手机竖版</div>`。
  - 颜色用 §4 的色值；加 `data-a="s"` 获得入场动画。
- 可选：写完先用你的去 AI 味/润色工具改一遍文案（要求：只改措辞、不改结构和字段名、长度不超过原文 105%），再 build。

页面类型（`## type`）：

| type | 用途 | 关键字段 |
|---|---|---|
| `cover` | 封面 | kicker title sub thesis orb core |
| `statement` | 一句大结论 + 可选组件 | kicker title lead visual |
| `agenda` | 主题目录，自动从 section/point 生成；条目可点击或键盘跳转 | kicker title（可手写 `- 组 | 项`） |
| `section` | 分组隔页（整页强调色） | title sub |
| `point` | 一个观点：左文右图 | title problem action visual note label num |
| `full` | 标题 + 整宽组件 | kicker title lead visual note |
| `compare`/`table` `flow`/`steps` `stats` `cards` `vs` `lanes` `bars` `list` `chips` `quote` | = `full` + 同名组件的简写 | 同 full |
| `loop` | 收束循环轮（3–8 步） | kicker title lead tags core，行=步骤名 |
| `end` | 深色结尾 | kicker title ty，行=关键词链 |
| `html` | 自定义 | title + ```html 块 |

## 3. 组件选型（visual）

| 观点长什么样 | visual | 行格式 | 行数上限（整宽/point 右侧） |
|---|---|---|---|
| 错误做法 vs 正确做法 | `vs` | `左 \| 右`，加 left/right/leftnote/rightnote | 5/4 |
| 有先后的步骤 | `steps`（整宽横排，point 内竖排；`dir: v` 强制竖排） | `步骤 \| 说明` | 6/5 |
| 同一件事两条路径（旧流程 vs 新流程） | `lanes` | `路径名 \| 环节1 \| 环节2 …`，最后一行高亮 | 3/2 |
| 比例/程度/前后变化 | `bars` | `标签 \| 宽度% \| 显示值`，标签前加 `~` 为弱化色 | 5/4 |
| 多方案多维度 | `table` | 首行 `cols:`，`win:` 高亮列 | 7/5 行，≤5/3 列 |
| 2–4 个关键数字 | `stats` | `数字单位 \| 标签 \| 注释`（`3.4 秒`→大数字+小单位）。数字过宽会自动缩小；4 位以上数字放 full 页更醒目 | 4/3 |
| 并列的 2–4 类 | `cards` | `角标 \| 标题 \| 要点1 / 要点2 \| 注释` | 4/3 |
| 清单/检查项/常见坑 | `list` | `标题 \| 说明` | 6/5 |
| 一组关键词/检查项（每个 ≤8 字） | `chips`（point 内为两列大块） | `词` | 10/8 |
| 金句/引用 | `quote` | 字段 quote、cite | — |

节奏：**不要连续 3 页用同一种组件**；每 4–5 页插一页不同版式（section/stats/statement）。

## 4. 设计系统（模板已实现，改风格就改这些变量）

- **画布**：固定 1600×900 的 `#stage`，按 `min(窗口宽/1600, 窗口高/900)` 等比缩放居中。所有尺寸按 1600 宽写 px。窗口宽 <760 且竖屏 → 手机模式 `body.m`：取消缩放，页面竖向滚动，字号单独一套。
- **页边距**：上 78 / 左右 96 / 下 92（底部留给页脚）。页脚 17px：品牌圆点 + 品牌名 + `NN / NN`。顶部 4px 渐变进度条。
- **颜色**（CSS 变量）：纸 `#F7F4EE`、纸2 `#EFEAE1`、墨 `#17183B`、墨2 `#4A4C66`、灰 `#8A8BA0`；强调色 珊瑚 `#FF5B3A`、紫 `#6C5CE7`、青 `#0FA394`、琥珀 `#E39400`、阳光黄 `#FFC23C`（只用于深底上的强调和封面主张左线）。每页只有一个强调色 `--ac`，由所在分组决定。背景 28px 点阵。
- **字体**：正文无衬线（PingFang SC / Noto Sans CJK / 微软雅黑），大标题衬线（宋体系，900），数字用 SF Pro/Inter。
- **字号阶梯（桌面 px）**：封面标题 118 / 分组页标题 110（配 300 号数字）/ 结尾 78 / 大结论 62 / 页标题 54 / 要点编号 128（描边）/ 副标题 34 / 正文 28（行高 1.75）/ 组件正文 21–27 / 小标题 kicker 20（字距 .12em + 28×3 色条）/ 页脚 17。**桌面最小 16px，手机最小 12px**（脚本会查）。
- **版式**：point 页网格 `560px + 1fr`，间距 60；文字左，图右。黑色"做法"卡片：墨色底、28px 白字、强调色胶囊标签。
- **动效**：元素带 `data-a` 依次入场，延迟 `200ms + 序号×85ms`，透明度 .75s、位移 .85s，缓动 `cubic-bezier(.2,.8,.2,1)`；变体 `l/r/s`（左入/右入/缩放）。翻页 .7–.8s，±70px 位移。进度条/条形图 1.4s 延迟 1s 生长。尊重 `prefers-reduced-motion`。
- **交互**：模板提供常驻导航和页面目录；具体行为见下面的规范，不能只保留快捷键或全页点击翻页。

### 4.1 主题目录：先让读者知道内容结构

主题目录是演示中的一页 `agenda`；页面总览是随时打开的导航面板，两者承担不同任务。

- 有多个章节或分组的讲解页，必须在封面／开场说明之后、首个章节之前放 `agenda`。线性短流程可用完整流程页代替主题目录，但仍保留常驻页面目录按钮。
- 按内容的自然主题分组，组名、颜色与章节一致；条目展示顺序编号和简短标题。默认自动生成，优先复用现有 `agenda`，不要手写第二套目录。
- 每个条目必须跳到对应页面，不能只做视觉卡片。手写条目时，标题须与目标页 `title` 一致；自动目录采用正文要点的顺序。重复标题或找不到目标时先修文案。
- 桌面按组分栏，手机竖排顺读；条目要可用 Tab 聚焦，并用 Enter／空格跳转。不要靠缩小文字塞入全部条目，超预算时拆分或归并主题。

### 4.2 页面总览：随时定位和返回

- 默认常驻“目录”按钮，打开包含**全部页面**的缩略图网格；每项有页码和短标题，当前页有明确边框标记。不能把只含正文要点的主题目录当成完整页面总览。
- 点击缩略图或聚焦后按 Enter／空格，跳到目标页并关闭总览；`O` 开关总览，`Esc` 关闭并保留原页。总览内滚动、选字和点击返回按钮不能触发演示翻页。
- 打开时焦点进入当前页项目；关闭后回到目录按钮。按钮声明 `aria-expanded` 和 `aria-controls`，总览有可访问名称；关闭状态的面板不能留在 Tab 顺序中。
- 桌面多列、手机减少列数并纵向滚动，所有页面均能到达；缩略图是定位预览，标题和按钮仍须清晰可读，不能把整张桌面总览缩成手机上不可操作的一屏。
- 缩略图显示完整内容，不受未播放的入场动画影响；预览不运行重复动画，不复制可聚焦控件或重复 ID。返回演示后恢复正常页面布局。

### 4.3 常驻按钮：可发现、可点击、状态明确

- 默认控件包括**上一页、当前页／总页数、下一页、目录、全屏**。放在独立的公共导航区，不逐页重复；为正文与页脚预留空间，手机考虑底部安全区。手机不支持或不适合全屏时可隐藏全屏按钮，目录与翻页始终可见。
- 使用真正的 `button`（显式 `type="button"`），图标按钮有与当前页面语言一致的可访问名称和提示；目录保留可见文字，不能只靠图标和快捷键让用户猜。按钮点击区至少 44×44 CSS 像素，不随幻灯片画布缩小到难以点击。
- 在公共样式定义默认、hover、focus-visible、disabled 状态。可点击按钮显式 `cursor:pointer`，首尾禁用按钮移除 pointer；浅色页、章节色底和深色结尾都要保持对比度。
- 第一页禁用上一页，最后一页禁用下一页；页码与当前页、地址栏 `#n` 一致。点击控件只执行其操作，不冒泡造成额外翻页。
- 保留快捷键：→ ↓ 空格 PageDown 回车 下一页；← ↑ PageUp 退格 上一页；Home／End；`O` 目录；`Esc` 返回；`F` 全屏。焦点在按钮、链接或目录条目时，Enter／空格执行其原生操作；输入框、编辑区和组合快捷键不被翻页逻辑截获。
- 保留左侧 30% 上一页、右侧 70% 下一页和手机左右滑动，但这些只是补充。链接、按钮、输入、表格横滑、总览滚动和文字选择均不能误触翻页。减少动态效果设置适用于按钮、总览和翻页动画。

只改风格：`--css extra.css` 追加覆盖（例如换 `:root` 里的颜色变量），不要改 build 出来的 HTML。

## 5. 生成与验收（循环直到全过）

```bash
python3 $SK/scripts/build.py deck.md -o deck.html --strict    # 文案预算检查
node   $SK/scripts/shot.js deck.html --out shots              # 截图 d01..dNN / m01..mNN + 自动查错
python3 $SK/scripts/sheet.py shots                            # 桌面总览图 shots/sheet-d-*.png（每张 12 页，超过就有 -2、-3，必须每张都看）
python3 $SK/scripts/sheet.py shots --prefix m --cols 6 --width 300 --per 18   # 手机总览图
node   $SK/scripts/key.js deck.html                           # 交互测试
# 或一条：bash $SK/scripts/check.sh deck.md
```

`shot.js` 报告含义与修法：

| 报告 | 含义 | 修法（按顺序试） |
|---|---|---|
| `OUT` | 元素超出页面或压到底部 60px 页脚区 | 删字 → 减行数 → 拆成两页 → 换更紧凑的组件。不要缩字号到阶梯以下 |
| `CLIP` / `CLIP text cut` | 文字被容器裁掉（含大号数字字形超出卡片） | 同上；或给该行更短的写法 |
| `SMALL` | 字号低于下限 | 用阶梯里的字号，不要为塞字缩小 |
| `HSCROLL` | 手机上页面能横向滚动 | 某个固定宽度元素在手机模式没改，给 `body.m` 加规则 |
| `OVERLAP` | 自绘 SVG 里文字压到/贴住方框或别的文字 | 挪坐标或缩短文字，留 ≥8 单位空隙 |
| `JSERR` | 脚本报错 | 先修，交互测试必挂 |

调参：`--wait 3400`（等入场动画播完，动画改长了就加）、`--only 3,7` 只拍某几页、`--mobile-pages 1,5` 、`--mobile off`、`--safe-bottom 60`。装饰元素确实要出界时加 `data-overflow-ok`。

**看总览图清单**（脚本查不出这些，必须自己 Read 图片看）：
1. 每页一眼能看出焦点：最大的字就是这页结论。
2. 没有"半页空白"：内容区下方空出 >35% 高度 → 加组件、换整宽组件或合并页。
3. 没有"挤"：组件和标题间距 ≥30px，卡片内文字没有贴边。
4. 颜色有含义：同组同色；红/灰只用于"不推荐"，绿/强调色用于"推荐"。
5. 节奏：相邻 3 页不是同一版式；section 页把节奏切开。
6. 封面标题 ≤3 行，右侧图形不压字；结尾页一句话能读完。
7. 手机图：每页从上到下能顺读，表格可横滑但页面本身不横滑，按钮/标签没有换成一字一行。手机截图只拍第一屏，下面被页脚挡住的是可滚动内容，不算错。
8. 桌面和手机分别打开页面目录，核对完整页数、当前页标记、可滚动范围、标题、按钮与焦点；主题目录跳转目标正确，返回后正文和导航不重叠。

## 6. 交付前：用户可见内容审查

页面只给读者看。逐页删掉：
- 制作过程话术："本页用 xx 组件""根据原文第 3 段""AI 生成""示例""TODO""占位"。
- 你的内部术语：skill、prompt、模型名、文件路径、脚本名（除非内容本身就讲这些）。
- 原文没有的数字和结论（数字必须能在原文找到出处，找不到就删）。
- 中英混排：英文术语首次出现可加中文；全文同一术语写法一致（如统一 `Agent` 或"智能体"）。

## 7. 常见坑

| 坑 | 表现 | 修法 |
|---|---|---|
| 把原文段落直接搬上页 | 每页一大段字、图像是装饰 | 回到 §1，每页只留 problem/action 两句 + 一张图 |
| 为了不越界把字号改小 | 投屏看不清，SMALL 报错 | 删字或拆页，字号阶梯不动 |
| 截图等待太短 | 截到半透明/没长出来的条形图，误判 | `--wait` ≥ 最长入场动画 + 0.5s |
| 只看桌面 | 手机上表格撑破、标签一字一行 | 每次都看手机总览图 |
| 单元格 ` \| ` 漏空格 | 一行变成一个格子 | 分隔符必须是"空格竖线空格" |
| 值以 `xx:` 开头被当成字段 | 文案丢半句 | 改写，避免行首 `英文词:` |
| 每页都同一组件 | 总览图像复印件 | §3 节奏规则 |
| 编数字 | 读者被误导 | 只用原文数字；没有数字就用 vs/steps 而不是 stats |
| 对比表 win 列全是 ✗ | 推荐项看起来最差 | ✓/✗ 按「该方案在这一行是否占优」标；"何时用/不用"这类表不设 win |
| 自绘 SVG 直接放 | 手机上字只有 5–6px，文字贴框 | 包 `.wide` 或做 `.only-m` 竖版；文字离框 ≥8 单位 |
| 只看第一张总览图 | 后半段的问题漏掉 | 页数 >12 时 sheet-d-2… 都要看 |
| 外链字体/图片 | 离线打开字体变丑、图裂 | 系统字体；图片转内联 SVG 或 base64 |
| 目录只有排版没有跳转 | 卡片能看但点了无反应 | 用匹配目标标题的 `agenda`，验证点击和键盘跳转 |
| 只给快捷键或全页点击 | 用户找不到目录或如何翻页 | 保留常驻导航；分别验收桌面、手机与深色页 |
| 直接改生成的 HTML | 下次 build 被覆盖 | 改 deck.md 或 extra.css |
